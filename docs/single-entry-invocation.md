# 单入口调用设计

## 给普通调用者的入口

完整核验任务优先调用“证链联研总控智能体”。调用者不需要知道三个专业智能体的
调用顺序，也不需要决定由谁汇总。总控会自动并行调用来源核验、证据分级和冲突侦测，
再返回一份 Evidence Passport。

最简单的调用可以直接提交一句自然语言：

> 请核验：结论“处理组观察到信号升高”；证据摘录“结果显示处理组信号升高，但该观察不单独证明因果关系”。

需要结构化输入时，最小 JSON 只有三个字段：

```json
{
  "schema_version": "1.0",
  "claim_text": "处理组观察到信号升高",
  "source_excerpt": "结果显示处理组信号升高，但该观察不单独证明因果关系。"
}
```

- `claim_text`：需要核验的结论；
- `source_excerpt`：支持或反驳该结论的原文摘录；
- `schema_version`：当前固定为 `1.0`。

AIP 调用时如果没有提供 `claim_id`，系统会自动采用平台 `taskId`，不再要求调用者
额外编写任务编号。来源编号、标题和定位信息也可暂缺；系统仍会完成核验，但来源核验
结果会明确标记为 `incomplete`，提醒后续补充，而不会伪造来源信息。

## 给高级调用者的入口

三个 Partner 继续保留独立调用能力，适合只需要某一种能力的其他智能体：

- 证链来源核验智能体：检查来源标识、标题、定位和摘录完整性；
- 证链证据分级智能体：判断证据对结论的支持强度；
- 证链冲突侦测智能体：识别摘录与结论间的方向相反、否定或转折冲突。

这三个入口是“可独立使用的专业工具”，不是普通用户完成整套流程前必须手工选择的
步骤。凡是需要完整 Evidence Passport 的调用者，只调用总控即可。

## 交互原则

1. 输入足以执行时直接运行，不询问调用顺序或汇总人。
2. 缺少可选元数据时运行并在结果中标注缺口。
3. 缺少证据摘录时仍返回可执行结果，并明确标记 `source excerpt is missing`；只有缺少待核验结论时才请求补充。
4. 不为增加调用量制造无意义互调；调用记录应来自真实任务、稳定运行和可复核输出。
